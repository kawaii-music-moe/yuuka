# 設定画面 再構成案

- 作成: 2026-10-22
- 元資料: [settings-inventory.json](settings-inventory.json)（2026-10-19 時点の、再構成前の一覧）
- 状態: 実装済み（`feat/settings-restructure`）

## 方針

1. **置き場所は「何に効くか」で決める。** 効く範囲ごとに入口を分ける。
   - このBot（`bot`）→ Bot設定
   - あなた × このBot（`user_bot`）→ Bot設定の中で、カードごとに範囲を示す
   - あなた全体（`user`）→ あなたの設定
   - 外部サービスの登録（`user`）→ 連携サービス
   - システム全体（`system`）→ 管理者設定
   - この端末（`client`）→ 各クライアントの設定
2. **階層はハブ → ページの 2 段まで。** 旧「Bot設定 → Bot基本設定 → 各カード」の 3 段はなくした。
3. **一度に出す量の上限を決める。** ハブは 1 カテゴリ 4 行まで、全体で 8 行まで。ページは 1 セクション 5 項目くらいまでにし、それを超えるページ（Playbook、汎用属性の Discord）はページ内タブで分ける。
4. **設定と操作を分ける。** 起動・停止のような運用操作は状態を見る画面（Bot一覧・ダッシュボード）へ移した。会話履歴のクリアのような取り消せない操作は、ページ末尾に置く。
5. **プリセットでカテゴリを消さない。** カテゴリの並びは固定し、使えないカテゴリは「秘書属性のBotで使えます」の 1 行に畳む。
6. **適用範囲バッジを出す。** 「このBot」「あなた × このBot」「あなた（全Bot共通）」「この端末」「システム全体」のどれかを、ページの見出し（範囲が 1 つのページ）かカードの見出し（範囲が混ざるページ）に出す。

## 全体構成

ホーム画面のサイドバー（`HomeSidebar`）:

```
ホーム（Bot一覧）     自分の Bot のカードに起動・停止ボタンを出す（旧 統合管理の health から移動）
あなたの設定          旧「アカウント管理」に、Bot基本設定の user スコープ項目と接続端末を合流
連携サービス          旧「統合管理」から health を外したもの
管理者設定            admin のみ。カテゴリ見出しを付けた
```

### Bot設定（`/bot/settings`）

```
このBot
  基本情報と共有  /bot/profile    Bot登録名・属性 ／ 利用できるメンバー・招待
  人格            /bot/personas   使用するペルソナ・ペルソナ編集・公開ペルソナ ／ 会話履歴のクリア
  機能と AI       /bot/features   有効な機能 ／ AI（汎用: Bot専用キー・モデル・利用量、秘書: 個人キーの案内）
  連携の利用許可  /bot/access     MCP サーバー（許可・提供ツール）／ 認証情報（閲覧）／ 使う Google アカウント
自動化            ※ 汎用属性では「秘書属性のBotで使えます」1 行に畳む
  Playbook        /bot/playbooks  [タブ] 手順書 ／ 定期実行 ／ 実行履歴
  定期配信        /bot/delivery   朝報 ／ 活動サマリー
  Webhook         /bot/webhooks   エンドポイント一覧 ／ 受信履歴
Discord
  Discord         /bot/discord    接続（Token・招待リンク・プロフィール同期）
                                  汎用属性のオーナーのみ [タブ] 応答する場所 ／ 応答する相手・利用申請 ／ ギルドノート
```

| 見る人・Bot | ハブの行数 |
|---|---|
| 秘書属性のBot | 8 行（3 カテゴリ） |
| 汎用属性のBot | 5 行 ＋ 畳んだ 1 行 |
| システムデフォルトBot（非 admin） | 6 行（基本情報と共有、Discord は非表示） |

基本情報と共有は、既定 Bot（`system_default`・`bot_default_*`）では行を出さない。オーナー以外が開いたときは「オーナーだけが変更できます」と出す。行の組み立ては `frontend/src/lib/botTabs.ts` の `hubGroups` にあり、上の行数はテスト（`botTabs.test.ts`）で確かめている。

### あなたの設定（`/account`）

```
プロフィール
  表示名とテーマ      表示名（あなた）／ 外観テーマ（この端末）
日々の動き
  時刻と通知          タイムゾーン・リマインド既定・通知先（チャンネル ID はチャンネル選択時だけ）・リッチ返信
  AI モデル           個人 Gemini API Key・使用モデル（PWA と共通）＋ どのBotがどのキーを使うかの説明
データ
  バックアップと移行  Google Drive 自動バックアップ ／ Bot移行パッケージ
セキュリティ
  ログイン中の端末    デスクトップアプリのダウンロード・端末一覧・失効
  アカウントの削除
```

6 行（4 カテゴリ）。

### 連携サービス（`/integrated`）

```
Google アカウント      連携アカウント・カレンダー設定 ／ 各Botで使うアカウント
MCP サーバー           登録（名前・URL・認証・確認要否・スコープ）／ Tool再取得 ／ 使えるBot
認証情報               登録（サービス・ユーザー名・パスワード・URL）／ 使えるBot
```

3 行。サービスの登録はここだけで行う。「どのBotに使わせるか」は次のとおり両側から扱える。どちらも同じデータを読み書きし、相互にリンクしている。

| | 連携サービス | Bot設定 › 連携の利用許可 |
|---|---|---|
| MCP サーバー | Bot ごとのチップで切り替え | このBotへの追加・解除（共有相手も可） |
| 認証情報 | Bot ごとのチップで切り替え | 閲覧のみ |
| Google アカウント | Bot ごとに選択 | このBotの分を選択（所有 Bot のみ） |

### 管理者設定（`/admin`）

```
システム
  システムデフォルトBot   Discord Bot Token
  全体設定                利用規約・プライバシーポリシー URL
  Bot属性と利用上限       プリセット表示名 ／ 汎用モードのレート制限
ユーザーとBot
  ユーザー管理
  Bot モデレーション
  公開ペルソナ管理
記録
  監査ログ
```

7 行（3 カテゴリ）。中身は変えず、見出しと名前だけ変えた。

### PWA・デスクトップ

- **PWA 設定**: 構成は今のまま。「使用モデル」に「管理画面のあなたの設定 › AI モデルと同じ設定です」と書いた（どちらも `users.gemini_model`）。エージェント選択には「この端末（ブラウザ）だけに保存されます」と書いた。
- **デスクトップ**: 見出しを「この端末の設定」にし、管理画面の設定とは別であることを書いた。

## 指摘事項への対応

| 指摘（designFindings） | 対応 |
|---|---|
| mixed-scopes-in-bot-config | Bot基本設定を解体した。user スコープは「あなたの設定」へ移し、Bot設定には bot と user_bot だけを残した。各ページか各カードに適用範囲バッジを出す |
| integration-management-split | 登録は「連携サービス」に一本化した。Bot側は「連携の利用許可」1 ページにまとめ、相互リンクを置いた |
| gemini-settings-duplication | 入力欄は残るが、どれが効いているかを書いた。秘書属性のBotは話しかけた人の個人キーとモデル、汎用属性のBotは Bot 専用キーとモデルで応答する（両者のあいだに引き継ぎは無い）。Bot設定 > 機能と AI と、あなたの設定 > AI モデルの両方にこれを書き、PWA には同じ設定であることを書いた |
| operations-mixed-with-settings | 起動・停止は Bot一覧とダッシュボードへ移した。会話履歴のクリアは人格ページの末尾に置いた。監査ログは管理者設定の「記録」に分けた |
| preset-dependent-navigation | カテゴリ（このBot / 自動化 / Discord）の並びを固定した。使えないカテゴリは理由付きの 1 行に畳み、行の位置がずれないようにした |
| cross-client-overlap | 適用範囲バッジと「◯◯と同じ設定です」の注記で、同期関係を画面上に書いた |

## 決めたこと

1. **バックアップは常に表示する。** 旧画面では「システムデフォルトBotを見ている非 admin」に出していなかったが、あなたの設定へ移したので Bot に関係なく出す。
2. **連携サービスは独立させたままにする。** 3 行だが、あなたの設定（6 行）と合わせると 9 行になるため。
3. **旧 URL は転送しない。** `/bot/config`・`/bot/devices`・`/bot/mcp` は未知タブとして既定タブ（ダッシュボード）を開く。`/account/gemini` など旧セクションのキーはハブを開く。

## API の追加

「あなたの設定」は Bot を選ばずに開くが、通知・バックアップ設定の現在値は Bot スコープの `GET /api/status`（`botId` 必須）でしか返していなかった。そこで次の 2 本を追加し、既存の `POST` と対にした。

| | 返すもの |
|---|---|
| `GET /api/settings/user` | `richReplyEnabled`・`remindDefaultMinutes`・`notifyTarget {type, id}`・`timezone` |
| `GET /api/settings/backup` | `enabled`・`folderId`・`intervalHours`・`generations`・`lastRunAt` |

- `/api/status` はタイムゾーンを返していなかったため、旧画面のタイムゾーン欄は常に空だった。新しい GET では返す。
- フォルダ ID は本人の Drive フォルダの識別子で秘密情報ではないため、編集できるようマスクせずに返す。`/api/status` はマスクした値を返すため、旧画面ではマスク値のまま保存すると形式エラーになっていた。

## インベントリの記載とコードの差分

案を作る途中で見つけた差分。インベントリは再構成前のスナップショットとして残す。

- **配信設定のスコープ**: インベントリでは `user`。実際は `briefing_configs` の主キーが `(user_id, bot_id)` なので `user_bot`。そのため Bot設定の下に残した。
- **アカウント管理**: インベントリには「パスワード変更」がある。今の `ACCOUNT_SECTIONS` にはなく、代わりに「Bot移行パッケージ」がある。
- **管理者設定**: インベントリには「招待コード管理」がある。今の `ADMIN_SECTIONS` にはない。
- **PWA の使用モデル**: アカウント管理の使用モデルと同じ `users.gemini_model` を読み書きしている（インベントリには関係の記載がない）。
- **会話履歴のクリア**: 旧画面ではオーナーの Bot にしか出していなかったが、API は Bot にアクセスできる人なら誰でも受け付ける。人格ページでは誰にでも出す。
